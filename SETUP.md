# Сборка с нуля

От чистой Windows до готового `.ipa`. Всё делается один раз; потом сборка —
это одна команда `make`.

Почему Windows и WSL, а не macOS: Theos собирает под iOS и на Linux, а
тулчейн, SDK и подпись целиком живут в пользовательском пространстве. Xcode
ни на одном шаге не нужен.

Понадобится около **5 ГБ** на диске (тулчейн 300 МБ, SDK 200 МБ, исходники
и сборка OpenSSL — остальное) и полчаса времени, из которых почти всё —
ожидание загрузок.

---

## 1. WSL2 и Ubuntu

В PowerShell **от имени администратора**:

```powershell
wsl --install -d Ubuntu
```

Команда ставит и саму подсистему, и Ubuntu. После неё нужна перезагрузка;
при первом запуске Ubuntu спросит имя пользователя и пароль — пароль
понадобится дальше для `sudo`.

Если WSL уже стоит, убедитесь, что это вторая версия:

```powershell
wsl --list --verbose
```

В столбце `VERSION` должна быть `2`. Первая версия тоже соберёт, но заметно
медленнее: у неё файловая система через эмуляцию.

Проверено на Ubuntu 24.04 и 26.04.

---

## 2. Исходники

Дальше всё — внутри Ubuntu (`wsl` в терминале Windows).

```bash
cd /mnt/c/Users/$USER/Documents/GitHub
git clone https://github.com/Computershik73/KiraLegacy.git
cd KiraLegacy
```

Класть проект на диск Windows не обязательно, но удобно: файлы видны обеим
системам сразу. Единственная плата за это — права: WSL выдаёт всему на диске
Windows `777`, а `chmod` там ничего не меняет. Makefile об этом знает и
складывает дерево пакета в `/tmp`, потому что `dpkg-deb` каталог с правами
`777` паковать отказывается.

Если клонируете в домашний каталог Linux (`~/KiraLegacy`), всё тоже работает
и даже быстрее.

## 3. Окружение

```bash
sh tools/setup.sh
```

Один заход, который делает всё остальное:

| шаг | что происходит |
|---|---|
| пакеты Ubuntu | `git`, `curl`, `perl`, `python3`, `zip`, `dpkg-dev` и прочее — через `apt`, спросит пароль |
| Theos | клонируется в `~/theos` |
| тулчейн | clang, умеющий целиться в iOS, около 300 МБ |
| SDK | `iPhoneOS9.3.sdk` в `~/theos/sdks`, около 200 МБ |
| заплатки к SDK | четыре исправления, без которых сборка не слинкуется или упадёт на устройстве |
| OpenSSL | 1.1.1w двумя срезами, armv7 и arm64 — самый долгий шаг, минут пять-десять |

Скрипт идемпотентный: всё уже стоящее он пропускает. Повторный запуск —
нормальный способ проверить, что окружение цело.

### Почему SDK именно 9.3

В новых SDK вырезаны заголовки эпохи iOS 5, а 9.3 — последний, где они живы
и где при этом ещё есть срез armv7. Тот 16.5, который обычно приезжает
с Theos, не годится.

### Почему SDK приходится чинить

В наборе Theos файлы `.tbd` перегенерированы, а не взяты у Apple, и при
перегенерации потерялась часть символов. Каждое из четырёх мест ломает
сборку по-своему и в разное время — подробности с объяснениями лежат
в самом `tools/patch-sdk.sh`, в заголовке.

Одно из них стоит назвать здесь: `libobjc.tbd` объявляет `NSObject`, хотя
до iOS 6 тот живёт в CoreFoundation. Без этой правки приложение собирается
без единого предупреждения и **не запускается** на iOS 5.1 — dyld отказывает
ещё до `main`, причём молча, без записи в журнале падений.

### Почему своя криптография

Secure Transport на iOS 5 и 6 предлагает только наборы шифров на CBC
и SHA-1: ни AES-GCM, ни ChaCha20, ни TLS 1.3 там нет, и задать другие нельзя
никак — это не настройка, а версия системы. Плюс `NSURLConnection` на старых
системах умеет замолчать навсегда, не соблюдая собственный `timeoutInterval`.
Поэтому весь HTTP в проекте свой, поверх сокетов и OpenSSL.

Версия 1.1.1w выбрана не от хорошей жизни: на 3.5.4 приложение падало внутри
машинерии провайдеров при разборе сертификата сервера. Подробности —
в заголовке `tools/build-openssl.sh` и в README.

## 4. Сборка

```bash
make                    # отладочная, проверить что компилируется
make package ipa        # .deb и .ipa в packages/
```

Готовое лежит в `packages/`:

* `KiraLegacy.ipa` — это `Payload/KiraLegacy.app` в zip;
* `ru.computershik.kiralegacy_1.0-N+debug_iphoneos-arm.deb` — для устройств
  с джейлбрейком.

Сборка идёт двумя срезами сразу и занимает минуту-полторы.

Если OpenSSL собран в другом месте, путь задаётся явно:

```bash
make SSL_OUT=$HOME/kiralegacy/out
```

## 5. Проверка готового файла

```bash
python3 tools/check-macho.py packages/KiraLegacy.ipa
```

Ожидаемый ответ:

```
KiraLegacy: универсальный файл, срезов 2
  срез armv7
    iOS, нижняя граница 5.1, SDK 9.3
    подпись:  adhoc, сводка SHA-1, имя ru.computershik.kiralegacy
    запасная: adhoc, сводка SHA-256, имя ru.computershik.kiralegacy
  срез arm64
    ...
Всё в порядке.
```

Проверять это не перестраховка. Всё, что здесь смотрится, компоновщик умеет
выставить неправильно молча, а замечается такое уже на устройстве — и не
на всяком. Приложение с платформой macOS запускается на iOS 6 и не
запускается на iOS 8, причём без записи в журнале падений: процесс не
падает, его просто не пускают.

Возвращает `1`, если хоть одна проверка не прошла, — годится для CI.

## 6. Установка на устройство

**С джейлбрейком** — `.deb` любым способом, каким ставятся твики: скопировать
на устройство и `dpkg -i`, либо открыть в Filza, либо положить в свой
репозиторий Cydia/Sileo.

**Без джейлбрейка** — `.ipa` через Sideloadly, AltStore или 3uTools. Они
переподписывают своим сертификатом, так что наша подпись при этом заменяется.

Подпись в пакете — adhoc, сразу обеими сводками: SHA-1 в основном слоте
и SHA-256 в дополнительном. Старая система читает первую и довольна, новая
берёт лучшую из имеющихся, и одна сборка проходит весь ряд от iOS 5 до 12.
Именно из-за этого в Makefile нет `-Hsha1`: он оставляет одну SHA-1, и тогда
на iOS 11 и 12 приложение снимается при запуске, тоже молча.

## Если что-то пошло не так

**`set: Illegal option -` при запуске любого скрипта из `tools/`.**
У файла виндовые переводы строк. В репозитории от этого стоит
`.gitattributes`, но если файл редактировали блокнотом или доставали
из архива — починить так:

```bash
sed -i 's/\r$//' tools/*.sh
```

**`dpkg-deb: error: control directory has bad permissions 777`.**
Сборка идёт не через `make`, а вручную, мимо `THEOS_STAGING_DIR`. Правильный
путь — `make package`: Makefile сам уносит дерево в `/tmp`.

**`ld: library not found for -lssl` или «нет `libssl.a`».**
OpenSSL не собран или собран не туда. Запустите `sh tools/build-openssl.sh`
и передайте путь: `make SSL_OUT=$HOME/kiralegacy/out`.

**`clang: error while loading shared libraries: libtinfo.so.5`.**
Тулчейну нужна пятая версия ncurses, а из свежих Ubuntu её выкинули.
Обходится ссылкой на шестую:

```bash
sudo ln -s /lib/x86_64-linux-gnu/libtinfo.so.6 /lib/x86_64-linux-gnu/libtinfo.so.5
```

**`file not found: /usr/lib/system/liblaunch.dylib` при компоновке.**
Не применены заплатки к SDK: `sh tools/patch-sdk.sh`.

**Собралось, но на устройстве не запускается и в журнале падений пусто.**
Почти наверняка `NSObject` привязан к `libobjc` — то же самое,
`sh tools/patch-sdk.sh`, и пересобрать. Проверить можно так:

```bash
~/theos/toolchain/linux/iphone/bin/nm -arch armv7 -m \
  .theos/obj/debug/KiraLegacy.app/KiraLegacy | grep NSObject
```

Должно быть `(dynamically looked up)`. Если вместо этого указана библиотека —
заплатка не применилась.

## Журнал с устройства

Приложение пишет всё, что уходит в системный журнал, ещё и в файл:

```
<песочница приложения>/Documents/kiralegacy.log
```

Предыдущий запуск сохраняется рядом как `kiralegacy-prev.log`, размер
ограничен полумегабайтом. Забрать файл можно Filza или любым файловым
менеджером с доступом к песочнице — это самый быстрый способ понять,
что произошло, когда что-то не работает.
